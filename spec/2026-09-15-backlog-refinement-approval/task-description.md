# Дополнение: reviewer workers не должны становиться отдельными Orca projects

При запуске review skill из executor наблюдался incident: `worker-start --worktree new-child` отказался создавать child worktrees, потому что текущий workspace зарегистрирован как folder project. Executor вручную создал два Git worktree и выполнил `orca repo add` для каждого. Orca зарегистрировал их как два отдельных проекта, поэтому UI показал два новых проекта вместо двух reviewer tabs текущего проекта.

Добавить в существующую финальную спецификацию требование проработать этот incident при реализации. Сохранить текущих reviewer workers и корректную изоляцию review, но запретить ошибочный обход, превращающий временных reviewer workers в отдельные проекты. Если нужно, провести одну дополнительную итерацию финального review.

Реализация в эту работу не входит.
