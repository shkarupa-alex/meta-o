# Возможности бэкенда

Meta-O поддерживает бэкенд только тогда, когда его публичная нативная
поверхность проходит общий контракт и реальные сценарии документа
[Сквозная проверка](e2e.md). Обязательное поведение имеет одного автора в
[Backend contract](../shared/references/backend-contract.md), а механика бэкенда
задаёт точные команды.

Поддержка конкретного запуска здесь не фиксируется. Версии диагностичны и не
прибиты. Бэкенд, потерявший извлечение полного финального ответа, обработку
вопросов или надёжное различение состояний, становится неподдерживаемым до
устранения наблюдаемого сбоя.

## Обязательные companion-скилы

| Бэкенд | Управление            | Обязательные companion-руководства |
| ------ | --------------------- | ---------------------------------- |
| Orca   | `orca` или `orca-cli` | `orchestration`, `orca-cli`        |

Управляющий исполняемый файл и каждое руководство проверяются отдельно. Наличие
исполняемого файла не доказывает, что агент знает семантику бэкенда.
Документированный пакет бэкенда подходящей версии считается источником
companion-скила, если полное руководство читается и управляющий агент прочитал
его до действий; установка в личный каталог среды агента для этого не нужна.

Работоспособность управления и готовность каждой среды агента — тоже разные
свойства. Готовность Orca должна быть доказана для каждой выбранной среды; общий
статус плоскости управления не отменяет сбой запуска поставщика.
