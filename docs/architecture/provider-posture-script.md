# §A-POSTURE-01 — У проверки готовности поставщика один источник и обязательные потребители

## Решение

`shared/scripts/mo-posture.sh` — единственный владелец диагностики разрешения
запуска в zsh/bash. Сборка побайтово копирует его в `mo-orchestrate-orca` и
`mo-setup`: каждая установка остаётся самодостаточной без прокси поставщика.

Потребители запускают его напрямую из установленного каталога:

```text
scripts/mo-posture.sh --self-check --shell all
scripts/mo-posture.sh --shell <zsh|bash|all> -- <selected-providers>
```

Проба классифицирует вид команды и первый путь во всех применимых режимах
оболочки. Она не запускает поставщика, не меняет конфигурацию, не хранит
состояние запуска и не решает, поддерживается ли бэкенд. Отсутствующее,
расходящееся, повреждённое или неполное доказательство не подтверждает поддержку.
Реальная готовность среды агента, активация модели, доверие, поведение разрешений
и режим без песочницы остаются проверками реальным запуском.

## Бизнес-причина

Режим запуска должен определяться детерминированно без обёртки над нативным CLI
поставщика. Один ограниченный помощник только для чтения у всех потребителей
предотвращает расхождение и не превращает личное поведение оболочки в угаданную
текстовую рецептуру.

Решение служит §B-PORTABILITY-01, §B-PORTABILITY-07 и §B-CONTROL-04: работа идёт
на уже настроенной среде агента без прокси, чужой интерфейс не угадывается, а лишний
управляющий слой не заводится. Если §A-POSTURE-01 отменяется, копии пробы в
двух скилах и её самопроверка удаляются, а диагностика возвращается в прозу
каждого скила по отдельности.

## §A-POSTURE-02 — Граница безопасности

Скрипт владеет одной группой процессов и читает закрытое дочернее доказательство
с NUL-разделителями. Он не печатает секреты поставщика или тела псевдонимов и
функций. Динамическое обнаружение моделей Claude отдельно использует
документированный жизненный цикл Agent SDK и не накладывает на поставщика
дополнительную платформенную песочницу с запретом ответвления процессов.

Изменения личной обёртки или профиля оболочки требуют явного подтверждения
пользователя. Агент не печатает защищённое определение; пользователь передаёт
подтверждённое представление без учётных данных или с удалёнными секретами.

Это §B-HUMAN-01 в конкретном виде: личная конфигурация меняется только с явного
подтверждения пользователя, а секреты не печатаются вообще.
Если §A-POSTURE-02 отменяется, изоляция закрытого доказательства, очистка группы
процессов и запрет на печать определений становятся лишними; такую пробу больше
нельзя считать безопасной для личной конфигурации.
