## Решение

Агент сначала устанавливает `in_scope`, `unconfirmed`, `project_issue`,
`upstream_issue`, `duplicate` или `needs_attention`, затем адресат. Для внешнего
владельца допустим только явно заданный пользователем репозиторий либо
проверенные метаданные владения инструмента; удалённый репозиторий проекта
никогда не служит резервным адресатом. Приоритет адресов Issue проекта: явно
заданный репозиторий, отслеживаемый удалённый репозиторий, `origin`.

Площадка выводится из хоста URL. Для корпоративного или самостоятельно
развёрнутого хоста требуется ровно один успешный аутентифицированный
`gh auth status --hostname` или `glab auth status --hostname`. Перед записью
выполняется ограниченный поиск открытых и закрытых Issues; усечённый результат
не доказывает отсутствие дубликата. Корневая причина совпадает только при той же
публичной поверхности, нарушенном инварианте и классе симптома.

Запись использует нативные `gh`/`glab`; финальные заголовок и явное тело из
закрытого временного файла проходят одну замкнутую политику удаления секретов
перед записью и последующим поиском результата. Неопределённый эффект не
повторяется. Закрытый исправленный Issue либо связывается с требуемой версией,
либо для нового случая использования создаётся новый Issue; автоматического
переоткрытия нет. Локальный обход публичного пробела содержит канонический URL
Issue внешнего владельца, иначе маршрут объявляется `unsupported`.

Трение самой методологии — такая же подтверждённая внешняя работа, и у него есть
отдельный класс `ISS-16`. Адресат один: репозиторий, названный в
`metadata.repository` установленного скила; без этого поля записи нет вовсе.
Пишут только скилы жизненного цикла, которые человек активировал явно, потому
что запись наружу из роли, которую человек не вызывал, — это действие от его
имени. Исполнитель, ревьюер, E2E-исполнитель и наблюдатель передают наблюдение
обычным сообщением `Methodology-Friction:`, а в прогонах эвалов и E2E наружу не
пишется ничего. Запись Issue остаётся действием внутри активированного скила и
не даёт никакому скилу права запуститься.

Решение служит §B-SELFHOST-03, §B-LONGEVITY-04, §B-HUMAN-04, §B-PORTABILITY-06 и
§B-PORTABILITY-07. Без §A-ISSUE-01 подтверждённая работа снова теряется в
локальном блокноте ветки, а нативные записи Issue лишаются проверяемых
маршрутизации, дедупликации, удаления секретов и контракта неизвестного эффекта.

## Переносимый эксплуатационный контракт

Каноническая таблица решений ISS-01…ISS-15, нативная поверхность CLI и
обязательная запись исхода принадлежат переносимому документу
[Маршрутизация подтверждённой внешней работы](../../shared/references/issue-routing.md).
Он механически входит в устанавливаемый `mo-orchestrate-orca`, поэтому внешняя
граница записи не зависит от доступа к исходному репозиторию Meta-O.

Наблюдения версии и учётных данных остаются доказательствами текущего запуска, а
повторяемые диагностические команды принадлежат
[Грабли и команды проекта](../papercut.md), не этому долговечному решению.
