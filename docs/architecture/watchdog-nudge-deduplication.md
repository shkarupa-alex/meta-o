# §A-WATCHDOG-01 — Наблюдатель дедуплицирует подсказки с помощью одного закрытого дайджеста

## Решение

Перед разрешённой подсказкой шаблонный наблюдатель хранит одну запись с режимом
`0600` на указатель бэкенда. Запись содержит дайджест бэкенда, указатель и
нормализованное нативное состояние, а также дайджесты сообщений, уже доставленных
в этом состоянии. Следующий запуск подавляет повтор сообщения, пока состояние не
изменилось. Новое состояние заменяет предыдущий набор сообщений. Запись не
хранит сообщение, ответ, реестр исполнителей, идентичность кандидата или
результат проверки.

Помощник разбирает JSON списка бэкенда через `jq`, сообщает каждый нативный
указатель отдельно и сравнивает специфичную для бэкенда смысловую проекцию. Для
Orca проекция сохраняет типизированные отправку, исполнителя, наблюдение и
состояние разрешений вместе с подключением или потерей терминала, но исключает
идентификатор RPC и поля терминала `preview`, `title` и `lastOutputAt`: это представление и
перерисовка, а не переход состояния, который должен блокировать доставку.
Доставка в Orca неблокирующая; последующее наблюдение отвечает за завершение.
Вызывающая поверхность цели или сканирования передаёт нативный вид элемента.
Проекция не угадывает его по случайным ключам метаданных и читает состояние
разрешений только из точного поля наблюдения, а не рекурсивным поиском вариантов.

Помощник принимает подсказку только после двух успешных одинаковых чтений. Зрелая
рекомендательная блокировка `flock` охватывает проверку дубликата, резервирование
и нативную доставку для указателя; ядро освобождает владение при завершении
процесса. Дайджест сообщения резервируется до доставки: сбой или ненулевой
результат бэкенда неоднозначны и остаются подавленными до изменения нативного
состояния, чтобы не рисковать повторной подсказкой. Шестнадцать разных дайджестов
сообщений в одном неизменном состоянии сворачиваются в один маркер насыщения:
запись остаётся ограниченной и закрытой с отказом до смены состояния.

## Бизнес-причина

Пользователю нужен наблюдатель, способный подтолкнуть агента, застрявшего на
лимите API или перегрузке инференса, не ожидая его ответа и не повторяя одинаковую
подсказку, когда отдельные запуски наблюдателя видят неизменное состояние. Без
долговечного отпечатка перезапущенный наблюдатель не выполнит второе требование.
Без разбора по сессиям сбойная сессия может скрыть работающую, а пользователь не
узнает, какая цель требует внимания.

Это §B-UPTIME-02 и §B-UPTIME-03: наблюдатель существует ради лимитов и
перегрузки, а пропущенное пробуждение считается дефектом. Именованное исключение
из общего запрета на хранилища состояния требует §B-CONTROL-04. Если §A-WATCHDOG-01
отменяется, закрытый дайджест, его блокировка и маркер насыщения удаляются
целиком, а наблюдатель возвращается к повторяющейся подсказке при неизменном
состоянии.

## Граница

Этот узкий отпечаток доставки — именованное исключение из общего запрета на
хранилища состояния. Это не состояние оркестрации: он не возобновляет и не
выбирает работу процесса. Удаление может вызвать повторную подсказку, но не
потерю продуктовой работы или недействительность кандидата. Для одноразового
тестирования каталог можно переопределить через `WATCHDOG_STATE_DIR`.
