# §A-REVIEW-02 — Обязательная единица ревью — одна пара моделей разных поставщиков

Статус: принято; субагенты ревьюера и отдельный чистый проверяющий отклонены.

```yaml
knowledge_id_change:
  action: reuse
  id: §A-REVIEW-02
  reason: Incident уточнил, что даже добровольная delegation нарушает проверяемую review unit.
  new_boundary: Lifecycle reviewer не создаёт subagents; независимость даёт ровно vendor-diverse pair.
  references_updated: true
```

## Решение

Финальный жизненный цикл фичи требует ровно одну независимую пару моделей разных
поставщиков на одном полном SHA. Четыре обязательных начальных ревьюера и
принудительные ансамбли 2×2 не являются дополнительной проверкой приёмки.
Субагенты ревьюера в жизненном цикле Meta-O запрещены: они размывают происхождение
одного авторского отчёта и делают изоляцию участников непроверяемой. Это не
запрещает отдельно запрошенное чистое ревью вне единицы ревью Meta-O.

Архивное исследование показывает, что одинаковые дополнительные голосующие
повышают стоимость и задержку, но не дают независимости модели; согласие может
скрыть правильное замечание меньшинства. Практический сбой этой программы
подтвердил границу: произвольная пара, не соответствующая контракту жизненного
цикла для разных поставщиков, дала ложный `PASS`, тогда как одна правильная пара
Claude/Codex нашла блокирующие дефекты. Поэтому принят ровно проверяемый контракт
пары, а дифференциальная оценка остаётся условием только для будущего пересмотра
границы, не отложенной обязательной работой.

Решение служит §B-PROOF-02, §B-REVIEW-03, §B-CONTROL-01 и
§B-SELFHOST-01.

## Если §A-REVIEW-02 отменяется

Отмена §A-REVIEW-02 требует заранее зарегистрированной дифференциальной оценки,
которая покажет измеримое улучшение над одной парой разных поставщиков при
сопоставимых ложных срабатываниях и стоимости. Тогда утверждения о точной паре и
ограничение одного вердикта на ревьюера становятся лишними и заменяются новым
контрактом жизненного цикла.
