# §A-RESPONSE-01 — Полный финальный ответ остаётся на публичных поверхностях бэкенда

```yaml
knowledge_id_changes:
  - action: reuse
    id: §A-RESPONSE-01
    reason: Authoritative worker_done получил обязательную проверяемую grammar.
    new_boundary: Полноту доказывают anchored sections и matching End-Review.
    references_updated: true
  - action: reuse
    id: §A-RESPONSE-01
    reason:
      No-overwrite handoff уточнил смысл полного settled response на уровне
      всего решения.
    new_boundary:
      Settled payload публикуется только create-if-absent и не может заменить
      ранее опубликованные bytes.
    references_updated: true
```

## Решение

Meta-O получает весь завершённый ответ ассистента только через документированную
публичную нативную поверхность Orca — полное сообщение оркестрации
`worker_done`. Orca-механика фиксирует точные команды установленной версии.

Полный вид сессии остаётся для редкой диагностики, но хвост терминала или
ограниченный предпросмотр не доказывают полный финальный ответ. Приёмка длинного
ответа требует узнаваемое начало, середину и конец на объёме примерно
трёх-четырёх экранов.

## Бизнес-причина

Ревью достоверно только тогда, когда каждый байт ревьюера доходит до
исполнителя. Закрытые расшифровки поставщика, хуки и выведенные из наблюдений
базы сессий — нестабильные детали реализации, способные незаметно выбрать не ту
сессию или ход. Просьба агенту повторить ответ проверяет послушание, а не
извлечение.

Решение служит §B-SESSION-02, §B-PROOF-01 и §B-PORTABILITY-07: полный финальный
ответ читается только с публичной поверхности бэкенда, нечитаемый целиком
вердикт не проходит проверку, а поведение берут у инструмента, а не угадывают.
Если §A-RESPONSE-01 отменяется, квалификация поверхностей и фикстуры нормального
и длинного ответа становятся лишними — вместе с уверенностью, что до исполнителя
дошло каждое замечание.

## §A-RESPONSE-02 — Следствие для доставки

```yaml
knowledge_id_change:
  action: reuse
  id: §A-RESPONSE-02
  reason:
    Delivery получила named consumer, atomic private namespace и acknowledgement
    boundary.
  new_boundary:
    Cleanup разрешён только после settled acknowledgement; caller публикует лишь
    authored severity census.
  references_updated: true
```

Два независимых ответа ревьюеров без изменений сохраняются в уникальном закрытом
временном пространстве имён с ограниченными правами. Только после завершения
обоих одно обычное сообщение передаёт названному потребителю оба точных пути и
оба размера. Оркестратор не объединяет, не ранжирует, не пересказывает и не
оценивает содержимое. Единственное исключение — сумма уже опубликованных
ревьюерами целочисленных количеств P0–P3; совпавшее замечание считается дважды.
Ошибка файла или полного чтения — `unknown`, а не частичный успех. Очистка
разрешена только после окончательного подтверждения потребителя и касается
только собственного пространства имён.

Неизменённая доставка — §B-REVIEW-01, а барьер до завершения обоих ответов —
§B-REVIEW-05 и §B-PROOF-02. Без §A-RESPONSE-02 исчезают временные файлы и
барьер, а вместе с ними независимость второго ревью.

## §A-RESPONSE-03 — Передача пары атомарна и принадлежит названному потребителю

```yaml
knowledge_id_change:
  action: reuse
  id: §A-RESPONSE-03
  reason:
    Review обнаружил, что ordinary rename может перезаписать уже опубликованный
    final payload.
  new_boundary:
    Publication использует atomic create-if-absent hard link; любой existing
    final остаётся неизменным и даёт UNKNOWN.
  references_updated: true
```

Вызывающая сторона под `umask 077` создаёт через безопасный `mktemp -d`
пространство имён с режимом `0700` в системном временном каталоге. Слоты A/B
назначаются до запуска; безопасный для пути идентификатор поставщика не является
идентичностью. Полезная нагрузка эксклюзивно пишется во временный обычный файл
`0600`, синхронизируется и закрывается, после чего полный inode публикуется
атомарно без перезаписи: жёсткой ссылкой в том же каталоге на финальный слот с
удалением временного имени. Переименование с возможностью перезаписи запрещено.
Вызывающая сторона перечитывает размер и `End-Review`, затем передаёт `pair_id`,
оба пути и оба размера.

Машинный потребитель после полного чтения отвечает ровно
`Review-Handoff-Ack: <pair_id> A=<bytes> B=<bytes>`. Один mismatch допускает
одну повторную доставку тех же путей; второй даёт `UNKNOWN` и сохраняет
пространство имён как доказательство. Вызывающий человек получает пути и размеры
в финальном ответе, автоматическая очистка запрещена. Существующий обычный файл,
символическая ссылка, необычный тип пути, неподдерживаемая жёсткая ссылка,
усечение или ошибка повторного чтения сразу дают `UNKNOWN` без изменения
существующего финального файла и без пересборки полезной нагрузки.

Решение служит §B-REVIEW-01, §B-REVIEW-05 и §B-SESSION-02. Отмена §A-RESPONSE-03
делает закрытое пространство имён, атомарную публикацию, повтор подтверждения и
очистку потребителем лишними, но доставка пары без потерь снова не доказуема.

## Отклонено

- закрытые расшифровки поставщика, хуки, базы сессий и хранилища целей;
- прямой невидимый вызов поставщика как резервный путь;
- маркеры завершения или файлы вердикта, созданные только ради Meta-O;
- реконструкция из фрагментов терминала;
- прокси поставщика или сервис адаптеров.
