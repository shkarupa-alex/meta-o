## Решение

Meta-O разрешает путь одного абсолютного исполняемого файла `orca`, читает из
него непустые встроенные руководства `orchestration` и `orca-cli`, фиксирует
версию и использует тот же исполняемый файл весь запуск. Руководства не
устанавливаются в домашний каталог среды агента.

До доставки байтов задачи создаётся терминал без полезной нагрузки; публичное
`tui-idle` и наблюдение согласованной версии обязаны доказать идентичность
процесса, нормальный `prompt` агента и отсутствие Claude Trust UI или `prompt`
оболочки. Только затем создаётся или внедряется один Dispatch. Составной запуск
разрешён лишь при публичном доказательстве, что полезная нагрузка удержана до
той же готовности. Обёртка является единственным владельцем режима без
песочницы; резервный путь не дублирует флаги. Неоднозначность делает маршрут
неподдерживаемым.

Простаивающая среда агента узнаётся по собственной рамке композера: у Claude —
линия над `❯`, у Codex — строка `›` прямо над его нижней строкой состояния, в
том числе когда та обрезана до `Context …`. Отправленный ранее запрос в
прокрутке композером не считается. Индикатор контекста читается, только если он
виден целиком, иначе он `unknown`. Текст в композере, которого пользователь,
возможно, не набирал, — подсказка Claude на экране или непустой `draft` — даёт
отказ и не стирается: пока Orca не сообщает происхождение этого текста, его
сходство с подсказкой ничего не доказывает. Переподключение к сессии разрешено
только при публично доказанных идентификаторе сессии, той же управляемой среде
агента и почтовом ящике с `worker_done`; `--continue` и живой терминал этого не
доказывают. После сбоя доверия Codex неудачный Dispatch освобождается по точному
идентификатору, доверие подтверждается процедурой ниже, и запускается та же
поддерживаемая среда; `orca terminal create --command "codex exec …"` ревьюером
не является.

Решение служит §B-PROOF-01, §B-PORTABILITY-01, §B-PORTABILITY-06 и
§B-PORTABILITY-07. Без §A-DELIVERY-01 задача может исполниться оболочкой или
попасть в Trust UI, а владение руководством, версией и режимом запуска перестаёт
быть доказуемым.

## Диалог доверия

Экран доверия больше не тупик, но и не обычный шаг. Агент подтверждает доверие,
только когда выполнены все три условия владения: терминал создан этим запуском и
записан в `OwnedResourceSet/1`; realpath пути из диалога совпадает с realpath
worktree, в котором создан этот терминал; сам worktree — ресурс запуска либо
корень проекта, явно названный пользователем при вызове. Условия проверяются
вместе, потому что подтверждение доверия — это ответ за всё содержимое папки, а
не нажатие кнопки: терминал чужого запуска, похожий путь и случайно открытый
каталог по отдельности выглядят безобидно и по отдельности ломают ровно это.

Процедура читает только записанные экраны: `accept_trust` при выделенном «No»,
одно нажатие вниз, повторное чтение обязано дать `confirm_trust`, и лишь затем
`Enter`. Неизвестная версия экрана, несовпавший путь, неподтвердившийся выбор,
завершившаяся среда и неизвестный эффект дают один и тот же исход без повтора:
закрывается точный дескриптор и возвращается `needs_attention` с рецептом
человеку. Повтор здесь опаснее отказа — он подтверждает доверие вслепую.

Отдельное публичное состояние Trust UI остаётся `unsupported` до появления
канонического URL: процедура выше проходима по экрану, но состояние «доверен ли
путь» из публичной поверхности прочитать нельзя. Факты версии и учётных данных
остаются доказательствами текущего запуска, а повторяемые диагностические
команды живут в [Грабли и команды проекта](../papercut.md). Смежный пробел
аудита фактической идентичности исполнителя уже ведётся в
[Orca issue #16527](https://github.com/stablyai/orca/issues/16527).
